Stack tecnológico propuesto

Todo TypeScript de punta a punta, en un monorepo con tipos y lógica de negocio compartidos.

Backend / API

  • NestJS 11 + Fastify · modular, DI, escalable
  • PostgreSQL 17 + Prisma 6 (migraciones, tipos)
  • Redis 7 · caché, locks, rate limit, sesiones
  • BullMQ · colas y workers para pedidos y sync
  • Meilisearch · búsqueda facetada y tolerante a typos
  • OpenAPI + Zod · contrato tipado y SDK generado
  • Cloudflare R2 / S3 · imágenes y activos de marca

Tienda (Storefront)

  • Next.js 16 App Router + React 19 · SSR/ISR para SEO
  • Tailwind CSS v4 + shadcn/ui (Radix)
  • next-intl · rutas con locale (/es, /en, /fr…)
  • next-themes · tema claro/oscuro + tokens de marca
  • TanStack Query + Zustand (carrito persistente)
  • Motion · microinteracciones · CSS moderno (container queries, :has, view transitions)

Panel Admin

  • Vite 7 + React 19 SPA (sin necesidad de SEO)
  • TanStack Router / Query / Table · grids potentes
  • shadcn/ui + Tailwind v4 · mismo design system
  • react-i18next · admin también multi‑idioma
  • dnd-kit + SSE · Kanban de pedidos en tiempo real
  • Recharts · analítica de ventas y márgenes
  • react-hook-form + Zod · formularios validados

Pedidos y escala

  • Máquina de estados del pedido con transiciones auditadas
  • Colas por prioridad + reintentos exponenciales + DLQ
  • Idempotencia en pagos y envío a proveedor
  • Outbox pattern · eventos de dominio fiables
  • Workers horizontales · escalado independiente de la API
  • Rate limiting por proveedor con token bucket en Redis

Proveedores

  • Adaptador genérico SupplierAdapter (interfaz única)
  • AliExpress DS API (Open Platform) como primer adaptador
  • Preparado para BigBuy, CJ Dropshipping, Spocket
  • Motor de precios · márgenes, redondeo, reglas por categoría
  • Sync incremental de stock/precio + sync completo nocturno

Pagos · por prioridad

  • 1 · NOWPayments — pasarela principal, 300+ criptos, tasa fija y conversión automática
  • 2 · Revolut — Merchant API + Revolut Pay (app y tarjeta)
  • 3 · Stripe — tarjeta, Apple/Google Pay, Bizum, SEPA
  • 4 · PayPal — alternativa de confianza
  • PaymentProvider · misma abstracción que los proveedores: añadir pasarela = añadir adaptador
  • Sin chargebacks en cripto · reembolso vía payout aprobado

Legal (ES/UE)

  • IVA 21%, OSS/IOSS, facturación con serie legal
  • Verifactu/SII · requisitos de facturación vigentes
  • RGPD/LOPDGDD · consentimiento, export/borrado de datos
  • Desistimiento 14 días · RMA y reembolsos
  • Cobros en cripto valorados en EUR al momento del cobro

Estudio de imágenes IA

  • ComfyUI autoalojado en GPU · workflows por API
  • BiRefNet (MIT) · recorte y fondo limpio
  • LaMa + PaddleOCR · quitar marcas de agua y texto chino
  • Real-ESRGAN / SUPIR · escalado y limpieza
  • SDXL · FLUX.1 schnell · Qwen-Image-Edit · pesos abiertos con licencia comercial
  • Modelos propios = sin política de contenido de terceros
  • Aprobación humana obligatoria antes de publicar

Infra y calidad

  • Turborepo + pnpm · monorepo con caché de builds
  • Docker Compose (dev) · contenedores en prod
  • GitHub Actions · lint, test, build, deploy
  • Sentry + OpenTelemetry + Grafana · trazas y alertas
  • Vitest + Playwright · unit, integración y E2E

Configuración: el panel manda

  • Todo lo configurable va en el admin, no en el servidor
  • Pasarelas, correo, almacenamiento, buscador, traductor, acceso social e IA
  • Credenciales cifradas (AES-256-GCM) y que no se vuelven a mostrar
  • Lo no configurado no se carga ni se ofrece · nada a medias
  • Cada integración se prueba contra el servicio real desde el panel
  • En .env solo lo que se lee antes de existir la base de datos

Estructura del monorepo

  • apps/api · NestJS (REST + webhooks)
  • apps/worker · procesadores BullMQ
  • apps/storefront · Next.js
  • apps/admin · React SPA
  • packages/db · Prisma schema y cliente
  • packages/shared · tipos, Zod, utilidades
  • packages/ui · design system compartido
  • packages/suppliers · adaptadores de proveedores
